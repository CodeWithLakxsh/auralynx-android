## Implemented features

Accessory engine (standard Bluetooth monitoring, BLE proximity decoding, model and capability
registries, AAP codec/session with confirmed commands and bounded recovery, proximity keys, RPA
resolution, encrypted battery), device dashboard and discovery with companion linking, battery
analytics and alerts, smart automation, 10-band equalizer (app-local + published sessions), recorder
with noise reduction/voice enhancement/WAV+AAC export, live translation (system on-device engine and
user-configured LibreTranslate), proximity finder, security & privacy center with redacted export and
delete-all, AirPods Max dashboard with sleep timer and volume-based exposure estimate, gesture bindings,
Quick Settings tiles, widget, dynamic shortcuts, status notification, monitor service, 18 required
screens plus discovery, gestures and rule editor. Details: IMPLEMENTATION_STATUS.md.

## Experimental features

App-local spatial audio (crossfeed, virtual speakers, virtual room), rootless channel experiment with
JSON export, Apple Continuity observer (Apple Watch research), head-tracking viewer with manual
calibration. All are behind the Experimental screen or labelled in place.

## Blocked features

| Feature | Blocker |
|---|---|
| Noise-control switching, adaptive level, conversation awareness, long-press cycle, rename, press events (gestures), AAP ear detection (auto-pause), 1 % battery, head tracking | **No public Android API opens a classic L2CAP channel** (verified in API 37.0/37.2 sources and at runtime: `invalid socketType - 3`). Auralynx does not use hidden-API bypasses. Implementation is complete and unit-tested; the runtime probe enables it automatically if Android adds the API. |
| Loud-sound reduction, hearing assistance, transparency customisation | Need Apple's Device ID in the phone's Bluetooth stack (root). |
| Heart rate (AirPods Pro 3) | Data format undocumented. |
| Signed release APK | No signing key configured (by design; CI signs when secrets are added). |
| Apple Watch pairing, notifications, health, calls | Unsupported: require an iPhone and Apple activation. |
| Find My network | Unsupported on non-Apple platforms. |

## Hardware validation status

**None.** No physical AirPods, AirPods Max or Beats were available. Protocol code is verified against
packets from public documentation and published test vectors (Bluetooth Core Spec `ah` vector, OpenSSL
AES vectors); engine behaviour against a scripted fake accessory. These are not hardware results.

## Known limitations

1. Accessory controls are unavailable on stock Android (see Blocked). The app is honest about it, but
   this removes the headline "noise control" use case for now.
2. Not tested on physical hardware, on Android < 16, or on non-Google OEM builds.
3. Equalizer reaches only Auralynx playback and players that publish their audio session, and only
   while Auralynx runs. Spatial audio is app-local.
4. On-device translation exists only where the phone ships a system translation service.
5. Background monitoring after reboot requires companion-device linking; without it, monitoring starts
   when the app is opened.
6. The local player has no background playback service (pauses with the process).
7. "Auralynx" coexists with an unrelated Google Play app named "Auralynx: Voice & Pulse"
   (`com.auralynx`); trademark clearance was not performed.
8. Build reproducibility: two forced full rebuilds of the same commit were byte-identical on one machine.
   Release APKs embed the git commit SHA, so hashes differ between commits by design. Cross-machine
   reproducibility is unverified.

## Recommended next steps

1. **Decide the accessory-channel policy** (maintainer decision): keep the public-API-only default and,
   optionally, ship a separate opt-in transport plugin for users who accept non-SDK APIs/root.
2. Run the device testing checklist on real AirPods (Pro 2/3 first) and at least three OEMs.
3. Configure release signing secrets, push the repository, tag `v0.1.0-alpha` to publish a pre-release.
4. Review the name/trademark situation before any store listing.
5. Add a MediaSession-backed playback service for the local player; on-device DSP profiling.
